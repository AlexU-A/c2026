Problem statement

The initial commit of ai_google_analytics ships working code, but the module's architecture does not yet meet Drupal contrib standards in several areas:

  • All cron logic lives as procedural code in ai_google_analytics.module with static \Drupal:: calls, no error handling, and a loop bug where only the last monitored page's data is ever saved.
  • hook_cron() and hook_mail() remain as procedural functions in the .module file rather than using the #[Hook] attribute pattern already established by the module's other hook classes.
  • The presave hook calls an AI agent to decide whether a Canvas page passes performance benchmarks, then regex-parses JSON from free-form LLM output to make a binary pass/fail decision. This makes the core behavioral decision non-deterministic, untestable, and fragile to LLM output variation.
  • Hook classes use static \Drupal:: calls throughout instead of constructor-injected services.
  • No *.services.yml — hook classes are not registered as services, making DI impossible and mocking in tests impractical.
  • No config schema (config/schema/) and no default config (config/install/ai_google_analytics.settings.yml), so drush config:inspect reports a missing schema and no config object exists until the settings form is saved.
  • The GoogleAnalytics AiFunctionCall plugin is missing the plugin.manager.ai_data_type_converter argument in its ::create() method (the parent FunctionCallBase::create() passes this, but the override omits it). It also has no credential validation, no property ID guard, no try/catch, and uses a static \Drupal::logger() call instead of an injected logger — any misconfiguration throws an unhandled exception during an AI agent session.
  • No composer.json, so the module cannot be packaged for drupal.org.
  • No README.md.
  • A critical security issue: the service account credentials JSON is uploaded to public://, making it publicly downloadable.
  • The helper function get_monitored_pages() is unprefixed, violating Drupal's global namespace rules.
  • The agent config for analytics_monitoring_agent declares no module dependencies (it references ai_context tools but does not declare ai_context as a dependency) and uses an overly complex structured output schema that is never consumed by any code.
  • No hook_uninstall() — the module's state entries (ai_google_analytics.context_data) persist after uninstall.

Steps to reproduce

  • Install the module on a Drupal CMS 2.0 / Drupal 11 site.
  • Run drush config:inspect ai_google_analytics.settings — reports missing schema.
  • Configure a service account and run cron with multiple monitored Canvas pages — only the last page receives GA data.
  • Open a page in the Canvas editor and trigger a presave — if the LLM returns output in an unexpected format, the pass/fail decision silently misbehaves.
  • Check the uploaded credentials file location — it is stored under public:// and accessible without authentication.
  • Uninstall the module — state entries remain in the database.

Proposed resolution

This merge request addresses the issues above through a coordinated set of changes. The changes fall into seven areas:

1. Extract cron logic to GoogleAnalyticsCronService

All GA API logic is moved from the procedural ai_google_analytics_cron() function into a new injectable service (src/GoogleAnalyticsCronService.php). The service receives config.factory, entity_type.manager, file_system, logger.factory, and path_alias.manager via constructor injection. Client instantiation and per-page API calls are each wrapped in try/catch — a single credential error or API failure no longer aborts the entire cron run. The cron loop bug (save outside the loop) and the early return (should be continue) are fixed.

2. Migrate all procedural hooks to OOP with #[Hook] attributes

hook_cron() and hook_mail() are moved from the .module file into GoogleAnalyticsHooks using #[Hook] attributes, matching the pattern already used by the module's other hook implementations. GoogleAnalyticsCronService is injected into GoogleAnalyticsHooks via constructor, making hook_cron() a one-liner delegation. The .module file is reduced to just the @file docblock.

3. Replace non-deterministic LLM pass/fail with BenchmarkEvaluator

A new src/BenchmarkEvaluator.php service performs deterministic PHP comparison of GA metrics against configurable thresholds. Three global thresholds (engaged_sessions_min, bounce_rate_max, key_event_rate_min) are stored in config and editable via the settings form. Three nullable float base fields on canvas_page entities allow per-page overrides (NULL means use the global default). The evaluator returns ['passed' => bool, 'failures' => string[]] with no AI involvement.

The presave hook now calls BenchmarkEvaluator::evaluate() for the pass/fail decision and calls the AI agent only when a page has already failed, to generate a human-readable summary for editors. Agent failure falls back to the deterministic failure descriptions, so an LLM outage never crashes an editor session. Passing pages clear any previously set flagged state (fixing a stale-state bug in the original).

4. Introduce ai_google_analytics.services.yml with full DI

All hook classes and new services are registered in ai_google_analytics.services.yml. GoogleAnalyticsHooks receives nine constructor-injected services: GoogleAnalyticsCronService, BenchmarkEvaluator, plugin.manager.ai_agents, plugin.manager.mail, config.factory, current_user, logger.factory, state, and request_stack. All static \Drupal:: calls in OOP classes are removed.

5. Add config schema and default settings

A new config/schema/ai_google_analytics.schema.yml defines the schema for ai_google_analytics.settings including the three benchmark threshold keys. A new config/install/ai_google_analytics.settings.yml provides empty defaults so the config object exists immediately after install. The settings form is updated to expose the benchmark thresholds.

6. Harden the GoogleAnalytics AiFunctionCall plugin and fix remaining issues

  • Added the missing plugin.manager.ai_data_type_converter argument to ::create() to match the parent FunctionCallBase constructor signature.
  • Replaced the static \Drupal::logger() call with an injected LoggerInterface property.
  • Early returns with descriptive messages for missing credentials, missing credentials file, and missing property ID.
  • The entire GA API call is wrapped in try/catch — errors are logged via the injected logger and a generic message is returned as tool output, rather than leaking exception details or throwing during an agent session.
  • Credentials upload location changed from public:// to private:// (security fix).
  • get_monitored_pages() renamed to ai_google_analytics_get_monitored_pages().
  • declare(strict_types=1) added to all files that were missing it.
  • Opening brace style corrected on class declarations to match Drupal coding standards.
  • Docblocks added to all classes and public methods.
  • The redundant \Drupal::state()->delete() immediately before ->set() on the same key is removed.
  • A hook_entity_delete() implementation is added to clean up ai_google_analytics.context_data state when a Canvas page is deleted, preventing orphaned entries in the review UI.
  • A hook_uninstall() implementation is added to remove the module's state entries on uninstall.
  • An install hook (hook_update_N 10001) installs the three per-page benchmark float fields on existing canvas_page entities via entityDefinitionUpdateManager.

7. Update agent config, declare dependencies, and add packaging files

  • The analytics_monitoring_agent config is updated to scope the agent to a summary-only role (it no longer evaluates pass/fail), structured_output_enabled is set to true, the schema is simplified to {summary: string, recommendations: string}, and the missing ai_context module dependency is declared.
  • The module .info.yml now declares ai_context:ai_context as a dependency, since the agent config references ai_context tools.
  • Library renamed from canvas_ai_init to ai_panel_bridge for clarity.
  • Module info.yml updated: description expanded, configure key added, canvas:canvas dependency added.
  • composer.json added with dependencies on drupal/ai, drupal/ai_agents, drupal/canvas, and google/analytics-data.
  • README.md added documenting the cron flow, presave agent trigger, review page, function call plugin, requirements, installation, and configuration.

PHPCS / PHPStan status

PHPCS (Drupal + DrupalPractice): 0 errors. 4 warnings remain — two File::load calls in the settings form (inherited from the original code) and two t()-with-variable warnings in the install file. Neither is a blocking issue.

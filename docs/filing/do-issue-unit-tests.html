Problem statement

The ai_google_analytics module has zero test coverage. The two most important code paths — benchmark threshold evaluation and the Canvas page presave hook — involve conditional branching, fallback behavior, and state management that are difficult to verify manually and easy to break during future changes.

Specifically:

  • The BenchmarkEvaluator service performs deterministic pass/fail comparisons against configurable thresholds with per-page override support. Without tests, boundary conditions and NULL-handling are unverified.
  • The presave hook in GoogleAnalyticsHooks orchestrates evaluation, conditional AI agent calls, state management, and email notification across several branches: unchanged metrics (skip), passing page (clear stale state), failing page with agent available, failing page with agent unavailable (fallback), new entity (skip), and entity delete (clean up state). These branches are untestable without the refactor that introduced constructor-injected services.

Dependency

This issue depends on [#3585742] "Refactor to service architecture with dependency injection, config schema, and packaging". The test files mock BenchmarkEvaluator and construct GoogleAnalyticsHooks via constructor injection — both require that issue's changes. Please merge the architecture refactor issue before this one.

Proposed resolution

Two PHPUnit test files covering the BenchmarkEvaluator service and the presave/delete hook logic in GoogleAnalyticsHooks. Both use UnitTestCase (no Drupal bootstrap required) and are compatible with PHPUnit 11 and PHP 8.3+.

BenchmarkEvaluatorTest — 8 test cases

File: tests/src/Unit/BenchmarkEvaluatorTest.php

The test constructs a real BenchmarkEvaluator instance with a mocked ConfigFactoryInterface providing global defaults: engaged_sessions_min = 100, bounce_rate_max = 70, key_event_rate_min = 2. Entity mocks use stdClass for field item lists rather than FieldItemListInterface mocks, because PHPUnit 11 does not support dynamic properties on interface mocks in PHP 8.3.

  • All benchmarks pass — metrics comfortably above/below thresholds, all overrides NULL; expects passed = true, empty failures array.
  • All benchmarks fail — metrics failing all three thresholds; expects passed = false, three failure messages each containing the metric name.
  • Single benchmark fails — only bounce rate exceeds threshold; expects exactly one failure message containing the actual value and the threshold value.
  • Per-page override takes precedence (lenient) — global bounce_rate_max is 70, page overrides to 90; a bounce rate of 85 should pass with the override in place.
  • Per-page override causes failure (stricter) — global engaged_sessions_min is 100, page overrides to 300; a value of 200 should fail against the stricter per-page threshold.
  • Empty metrics pass — NULL field values; expects passed = true (no data means no failure).
  • Empty string metrics treated as NULL — GA API can return empty strings for metrics with no data; expects passed = true, same behavior as NULL.
  • Boundary values pass, just-past boundary fails — two cases: metrics exactly at threshold pass; metrics at threshold +/- 0.1 fail all three.

GoogleAnalyticsHooksPresaveTest — 7 test cases

File: tests/src/Unit/GoogleAnalyticsHooksPresaveTest.php

The test constructs GoogleAnalyticsHooks directly via constructor injection, passing mocks for all nine dependencies: GoogleAnalyticsCronService, BenchmarkEvaluator, plugin.manager.ai_agents, plugin.manager.mail, config.factory, current_user, logger.factory, state, and request_stack. Each test case configures the mocks to exercise a specific branch.

  • Unchanged metrics skip evaluation — entity original has identical GA field values; BenchmarkEvaluator::evaluate() is never called, state is untouched.
  • Passing benchmarks clear stale state — evaluator returns passed = true; the hook calls StateInterface::delete() to remove any previously set flagged state.
  • Failing benchmarks call agent and update state — evaluator returns passed = false; the hook retrieves the AI agent plugin, calls it for a summary, and calls StateInterface::set() with the result.
  • Agent failure falls back to deterministic text — evaluator returns passed = false, agent plugin throws an exception; the hook catches it, falls back to the failures array from the evaluator, and still calls StateInterface::set() with the fallback content.
  • Non-Canvas-page entities are skipped — entity bundle is not canvas_page; BenchmarkEvaluator::evaluate() is never called.
  • New entities (no original) are skipped — entity has no original property; the hook exits early before evaluation.
  • Entity delete clears state — hook_entity_delete() is called with a canvas_page entity; StateInterface::delete() is called with the correct state key.

Running the tests

phpunit --group=ai_google_analytics

Or with DDEV:

ddev exec phpunit web/modules/custom/ai_google_analytics/tests --group=ai_google_analytics

Both test classes use UnitTestCase with no database or container bootstrap. They run in under 100ms.
